# テスト計画（マップ）

## 1. テスト全体方針・フェーズ構成

WinAuth v4.0 の品質保証は、以下の 3 段階のテストレベルを組み合わせて実施します。

| テストレベル | 対象範囲・目的 | 実施方式・基盤 | 関連ドキュメント / 実装 |
| --- | --- | --- | --- |
| **単体テスト (UT)** | RFC 6238/4226 算出アルゴリズム、`WINAUTH4` 暗号化・改ざん検知・`WINAUTH3` 互換復号、XXE/ReDoS/XSS/ドリフト防御、MetroForm 座標配置、設定バージョン制御、多言語判定/フォールバック、UIフォント・表示レイアウトの検証 | `dotnet test` (xUnit 自動テスト) | `Authenticator.Tests/` (`RfcTests`, `Phase2SecurityTests`, `Phase3CryptoTests`, `Phase4SecurityTests`, `BugFixTests`, `UiEnhancementTests`) |
| **結合テスト (IT)** | モジュール間連携（UI ⇄ `WinAuthConfig` ⇄ `Authenticator`）、ファイル I/O アトミック保存、外部 HTTPS API 連携（Steam / Battle.net / Trion / Google）、YubiKey P/Invoke 連携、OS API 連携の検証 | xUnit 結合検証 + モック/実機確認 | `42_結合テスト観点.md`, `44_結合テスト.md` |
| **システムテスト (ST)** | エンドツーエンド業務シナリオ、多層保護運用、ポータブル/CLI起動、レガシー移行・上位バージョン保護、UIリサイズ追従、および GitHub Actions リリースパイプラインの総合検証 | 実機シナリオ検証 + CI パイプライン検証 | `43_システムテスト観点.md`, `45_システムテスト.md` |

---

## 2. テスト環境および合格基準

- **対象 OS / ランタイム**: Windows 10 / Windows 11 (x64)、.NET 10 SDK / Desktop Runtime (`net10.0-windows`)
- **合格基準**:
  1. `dotnet test WinAuth.sln -c Release` の全自動テストケースが 100% 成功（Failed = 0）すること。
  2. セキュリティ要件（`NFR-001`〜`NFR-005`：改ざん検知、ヘッダー除去拒否、XXE遮断、24h超ドリフト棄却、秘密情報非露出）の検証項目がすべて期待通り防御動作すること。
  3. 旧形式（`WINAUTH3` / v3.x）からの移行および上位バージョン（v4.5等）読み込み時のデータ破壊が 0 件であること。
