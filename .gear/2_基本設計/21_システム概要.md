# システム概要

## 1. システム構成概要
WinAuth は、Windows デスクトップ環境でスタンドアロン動作する二要素・多要素認証（2FA / MFA）クライアントアプリケーションです。外部クラウドへのアカウント同期を行わず、ローカルの暗号化構成ファイル（`winauth.xml`）で秘密鍵を安全に完結管理できるポータブル性を特徴とします。

システムは以下の 4 つの論理レイヤで構成されます。
1. **プレゼンテーション層（`WinAuth` / `MetroFramework`）**: Windows Forms と MetroFramework によるモダン UI フォーム群、オーナードロー認証器リスト（`AuthenticatorListBox`）、システムトレイ制御、トースト通知。
2. **アプリケーション・OS連携層（`WinAuth` / `InputSimulator`）**: 設定管理（`WinAuthConfig` / `WinAuthHelper`）、インポート・エクスポート（KeyUri / ZIP / OpenPGP）、グローバルホットキー（`KeyboardHook`）と自動キー入力（`SendInput`）、単一インスタンス制御（`SingleGlobalInstance`）。
3. **認証・暗号コア層（`Authenticator`）**: RFC 6238 TOTP / RFC 4226 HOTP 基底エンジン、サービス別認証プロトコル実装（Google / Microsoft / GuildWars / Okta / Battle.net / Steam / Trion）、および `WINAUTH4` 認証付き暗号基盤（AES-256-GCM + PBKDF2-SHA256 / HKDF + DPAPI）。
4. **ハードウェア・外部通信層（`WinAuth.YubiKey` / HTTPS Client）**: USB HID 経由の YubiKey C ネイティブ DLL 連携、および TLS 1.2/1.3 による外部認証・時刻同期サーバー連携。

## 2. v4.0 における主要改修・刷新サマリー

| 区分 | 対象領域 | 旧仕様（v3.x 系） | 現行仕様（v4.0 刷新後） | 互換性・効果 |
| --- | --- | --- | --- | --- |
| 刷新 | ランタイム・ビルド | レガシー .NET Framework / ILMerge | **.NET 10 (`net10.0-windows`)** / `PublishSingleFile` 単一EXE発行 | 最新 Windows 10/11 環境での高速動作と保守性確保 |
| 刷新 | 暗号化基盤 | `WINAUTH3`（PBKDF2-SHA1 2,000回 + AES-CBC、改ざん検知なし） | **`WINAUTH4`**（PBKDF2-SHA256 **600,000回** + **AES-256-GCM** + AAD完全性検証） | 改ざん・ヘッダー除去を100%検知。`WINAUTH3` 透過復号および `.v3.bak` 自動退避を維持 |
| 強化 | XML・入力検証 | 標準 `XmlReader`、無制限正規表現、平文含有例外 | `SafeReaderSettings`（DTD禁止）、`Regex.Escape`＋500msタイムアウト、秘密情報非露出化 | XXE 攻撃・ReDoS 攻撃・エラー経由のシークレット漏洩を防止 |
| 強化 | 通信・クリップボード | HTTP混在、任意の時刻差適用、無期限クリップボード保持 | HTTPS（TLS 1.2/1.3）強制、**24時間超ドリフト棄却**、履歴除外＋**30秒自動クリア** | MITM 時刻改ざん攻撃およびクリップボード経由の漏洩を防止 |
| 強化 | 設定保護・UI・ハードウェア | 上位バージョン読込破壊リスク、リサイズ時のボタン座標ずれ、DLL不在時クラッシュ | 上位バージョン検知時 **`IsReadOnly` 強制**、MetroForm 動的追従、`LibraryNotFoundException` 捕捉 | データ破壊防止、UI崩れ解消、YubiKey DLL 不在時の安全な動作継続 |

## 4. 主要データフロー概要

1. **起動・設定ロードと復号フロー**
   - コマンドライン引数、実行ファイル同階層（ポータブルモード）、または `%APPDATA%\WinAuth\winauth.xml` の優先順で設定ファイルを解決し、絶対パスへ正規化する。
   - `Authenticator.SafeReaderSettings`（DTD 禁止）で XML を解析し、`version > 4.0` の場合は `IsReadOnly = true` を設定する。
   - `<data encrypted="...">` が存在する場合は `DecryptSequence` を呼び出す。`WINAUTH4` ヘッダー時は DPAPI 解除後に AAD を構築し、PBKDF2-SHA256（600,000回）または YubiKey + HKDF で導出した鍵により `AesGcm` 認証付き復号を行う。`WINAUTH3` ヘッダー時は後方互換復号を行う。
2. **OTP 算出・表示・入力支援フロー**
   - `mainTimer`（1秒周期）により自動更新対象の TOTP 認証器のタイムステップ境界を監視し、`CurrentCode` の再計算と円形インジケーター再描画を行う。HOTP は手動クリック時にカウンターを加算して算出する。
   - コピー時は履歴・クラウド同期除外属性付き `DataObject` をクリップボードに設定し、30秒後に一致確認のうえ自動消去する。グローバルホットキー押下時は `Notify` / `Copy` / `Inject` / `Advanced` の各アクションを実行する。
3. **アトミック永続化フロー**
   - メモリ上で XML を構築・非ゼロ検証後、`winauth.xml.tmp` に書き出して全バイト読み戻し一致を確認する。
   - 初回 `WINAUTH3` → `WINAUTH4` 移行時は `winauth.xml.v3.bak` を保全した上で、既存ファイルを `.bak` に退避し `.tmp` を本体へ置換する。

## 5. セキュリティ設計と脅威対策一覧

| 対象脅威 | 対策内容（実装クラス・メソッド） |
| --- | --- |
| 暗号文改ざん・ダウングレード攻撃 | `Authenticator.EncryptSequenceV4` / `DecryptSequenceV4` にてヘッダー・保護種別・反復回数・ソルトを AAD として AES-256-GCM で検証。ヘッダー除去時も平文・旧方式へフォールバックせず `BadPasswordException` で拒否。 |
| メモリ上の秘密鍵残留 | 鍵導出後のパスワードバイト列・派生鍵・平文バイト列を `finally` ブロックで `CryptographicOperations.ZeroMemory` により即座にゼロクリア。 |
| XML 外部実体参照（XXE） | `Authenticator.SafeReaderSettings` および `XmlDocument.XmlResolver = null` により外部エンティティ解決を全面禁止。 |
| 正規表現 DoS（ReDoS）・XSS | Issuer 解析時の `Regex.Escape` + 500ms タイムアウト、`WinAuthHelper.HtmlEncode` による `'`（`&#39;`）含むサニタイズ、通信パラメータの `Uri.EscapeDataString` 適用。 |
| 時刻改ざん（Time Spoofing） | TLS 1.2 / 1.3 強制に加え、`ServerTimeDiff` が ±24時間を超える応答を異常値として棄却。 |
| クリップボード・例外情報漏洩 | クリップボードの履歴除外フラグ付与と30秒自動クリア、およびカスタム例外クラスからの平文秘密情報出力の排除。 |

## 6. 動作環境およびビルド・配布構成

| 項目 | 仕様 |
| --- | --- |
| 対応 OS | Windows 10 / Windows 11（64ビット環境推奨） |
| 必須ランタイム | .NET 10 Desktop Runtime（`10.0.x`） |
| 設定保存先 | 標準: `%APPDATA%\WinAuth\winauth.xml` / ポータブル: `<WinAuth.exeと同フォルダ>\winauth.xml` / 任意パス引数指定可 |
| ログ出力先 | `%APPDATA%\WinAuth\winauth.log`（フォルダ非存在時は EXE 同階層、既定ログレベル `Error`、`-l` 引数で変更可） |
| 配布形式 | GitHub Actions（`release.yml`）により生成される単一実行ファイル格納 `WinAuth-<tag>.zip` および `.sha256` チェックサムファイル |
