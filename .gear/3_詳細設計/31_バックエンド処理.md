## 2. 主要アルゴリズム・内部ロジック詳細

### BP-001 / BP-002 OTP 算出ロジック
1. **タイムステップ / カウンター決定**:
   - TOTP: `CodeInterval = (CurrentTime + ServerTimeDiff) / (Period * 1000L)` を Big-Endian 8byte 配列へ変換。
   - HOTP: `Counter` を `+1` インクリメントし Big-Endian 8byte 配列へ変換後、変更イベントを発火して設定保存を予約。
2. **HMAC 計算と動的切り詰め（Dynamic Truncation）**:
   - `HMACType`（`SHA1` / `SHA256` / `SHA512`）のダイジェストで HMAC を算出し、末尾バイトの下位4bit `offset = mac[mac.Length - 1] & 0x0F` から4byteを抽出して最上位符号ビットをマスク（`& 0x7FFFFFFF`）。
   - 一般 TOTP/HOTP/Battle.net/Trion は `10^CodeDigits` の剰余をゼロ埋め文字列化し、Steam Guard は 26文字テーブル（`23456789BCDFGHJKMNPQRTVWXY`）で5回除算変換を行う。

### BP-006 WINAUTH4 暗号化・復号ロジック
1. **暗号化 (`EncryptSequenceV4`)**:
   - 16byte `salt` と 12byte `nonce` を CSPRNG（`RandomNumberGenerator`）で生成。
   - 鍵導出: `Explicit` 指定時は `Rfc2898DeriveBytes.Pbkdf2(password, salt, 600_000, SHA256, 32)`、`YubiKey` 指定時は 32byte チャレンジ応答に対して `HKDF.DeriveKey(SHA256, response, 32, salt)`、DPAPI 単独時はランダム 32byte `innerKey` を生成。
   - AAD 構築: `"WINAUTH4"(8B) || BigEndian(passwordType)(4B) || BigEndian(600000)(4B) || salt(16B)`（計32byte）。
   - `AesGcm`（16byte タグ）で暗号化後、ペイロードを構築し、指定に応じて `ProtectedData.Protect`（`CurrentUser` → `LocalMachine` の順）でラップする。`finally` 句で鍵・平文配列を `CryptographicOperations.ZeroMemory` で消去。
2. **復号 (`DecryptSequence` / `DecryptSequenceV4`)**:
   - 先頭ヘッダーが `WINAUTH4` であれば DPAPI を逆順（`LocalMachine` → `CurrentUser`）で解除し、AAD と 16byte タグを用いて `AesGcm.Decrypt` を実行。タグ不一致・ヘッダー欠落・短小ペイロードはすべて `BadPasswordException` を送出。
   - 先頭ヘッダーが `WINAUTH3` の場合のみレガシー復号（`DecryptSequenceV3`）を実行し、未知ヘッダーやヘッダー除去データに対する平文フォールバックは一切行わない。

### BP-009 安全な XML 解析・アトミック保存ロジック
- **読込時**: `Path.GetFullPath` で絶対パスへ正規化し、`SafeReaderSettings`（`DtdProcessing.Prohibit`, `XmlResolver = null`）で XXE を遮断。ルート `@version > CURRENTVERSION (4.0)` の場合は `IsReadOnly = true` を強制設定する。
- **保存時**: `IsReadOnly == true` の場合は書き込みを抑止。通常時は `MemoryStream` 上で非ゼロ検証後、`.tmp` ファイルへ書き出して `File.ReadAllBytes` で完全一致を検証。既存ファイルが `WINAUTH3` を含む初回保存時は `.v3.bak` を残した上で、既存を `.bak` へ移動し `.tmp` を本体へリネームする。
