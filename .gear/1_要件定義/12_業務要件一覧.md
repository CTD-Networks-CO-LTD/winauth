# 業務要件一覧

WinAuth における業務（利用・運用・セキュリティ管理）上の要件を以下に定義します。

| 要件ID | カテゴリ | 要件名 | 優先度 | 詳細説明 |
| --- | --- | --- | --- | --- |
| BR-001 | 認証管理 | 標準規格に基づくワンタイムパスワード生成 | 高 | RFC 6238（時間ベース TOTP）および RFC 4226（カウンターベース HOTP）に準拠し、シークレットキーと補正時刻またはカウンター値から正確なワンタイムパスワード（6〜8桁等、HMAC-SHA1/SHA256/SHA512対応）を算出・表示できること。 |
| BR-002 | 認証管理 | 主要ゲーム・Webサービス固有の二要素認証対応 | 高 | Google Authenticator、Microsoft Authenticator、Okta Verify、Guild Wars 2 に加え、独自プロトコルを持つ Battle.net（8桁・シリアル/リストアコード対応）、Steam Guard（5桁英数字・モバイル登録対応）、Trion / Glyph（8桁・デバイスキー登録/復元対応）の認証器を統合管理できること。 |
| BR-003 | セキュリティ管理 | 多層暗号化（WINAUTH4）による認証情報の保護 | 高 | マスターパスワード（PBKDF2 600,000反復 + AES-256-GCM 認証付き暗号）、Windows DPAPI（現在ユーザー / ローカルマシン限定）、および認証器単位の個別パスワード保護により、保管データの機密性と完全性（改ざん・ヘッダー除去検知）を確実に保護すること。 |
| BR-004 | ハードウェア連携 | YubiKey ハードウェアトークンによる鍵保護 | 中 | USB 接続された YubiKey（HID デバイス）のスロット 1 または 2 に対する HMAC-SHA1 チャレンジ・レスポンスおよび HKDF 鍵導出を用いて、設定データの暗号化・復号保護を行えること。未接続・DLL非存在時もクラッシュせず安全に制御すること。 |
| BR-005 | 時刻同期 | 外部サーバーとの時刻同期および異常ドリフト防御 | 高 | クライアント端末の時計ズレによる認証失敗を防ぐため、外部サーバー（Google、Steam、Battle.net、Trion）と HTTPS 通信して時刻差分（`ServerTimeDiff`）を補正すること。24時間を超える極端な時刻差は攻撃・異常値として棄却すること。 |
| BR-006 | トレード管理 | Steam モバイルトレード確認の照会・承認・拒否 | 高 | Steam Web API および Steam Community モバイル確認機能と連携し、保留中のアイテムトレードやマーケット出品の一覧照会・詳細表示・承認・拒否、およびバックグラウンド自動ポーリング（自動承認・通知）を行えること。 |
| BR-007 | デスクトップ操作性 | 迅速かつ安全なコード入力支援（コピー・ホットキー） | 高 | ワンタイムパスワードのワンクリックコピー（履歴除外フラグおよび30秒後の自動消去付き）、システムトレイ常駐、グローバルホットキーによるコード通知・対象ウィンドウへの自動キー入力（Auto-Type）を提供し、認証操作の手間を最小化すること。 |
| BR-008 | データ移行・保全 | バックアップ・インポート/エクスポートと互換性維持 | 高 | `otpauth://` URI 形式テキスト、パスワード付き ZIP、OpenPGP 暗号化によるエクスポート/インポートおよび QR コード画像読取に対応すること。また旧形式（`WINAUTH3` / v3.x / v2.x）の透過的読み込みと上位バージョンファイルの上書き破壊防止を実現すること。 |
| BR-009 | 運用形態 | ポータブル運用および起動オプション制御 | 中 | インストール不要の単一実行ファイルとして動作し、`WinAuth.exe` と同階層に `winauth.xml` を配置した際はレジストリを変更しないポータブルモードで動作すること。また最小化起動・プロキシ指定・設定ファイル指定等のコマンドライン引数に対応すること。 |
| BR-010 | UI・保守運用 | 統一されたモダンUIと品質・リリース自動化 | 低 | MetroFramework による視認性の高い UI・テーマ切替・カスタムアイコン設定・異常時の診断機能を提供するとともに、GitHub Actions による自動テスト・単一バイナリ生成・SHA-256 チェックサム付与を自動化すること。 |
