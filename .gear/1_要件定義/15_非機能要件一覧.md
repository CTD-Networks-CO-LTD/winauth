# 非機能要件一覧

セキュリティ強度、互換性、可用性、性能、および運用保守性に関する非機能要件と達成基準を以下に定義します。

| 要件ID | カテゴリ | 要件名 | 目標基準・実装仕様 | 優先度 |
| --- | --- | --- | --- | --- |
| NFR-001 | セキュリティ | 認証付き暗号（WINAUTH4）による機密性・完全性保証 | 旧 `WINAUTH3`（PBKDF2-SHA1 2,000反復 + AES-CBC、改ざん検知なし）から **`WINAUTH4`**（PBKDF2-HMAC-SHA256 **600,000反復** + **AES-256-GCM** + 16byte タグ + AAD ヘッダー束縛）へ刷新すること。暗号文改ざん・誤パスワード・ヘッダー除去攻撃を 100% 検知して `BadPasswordException` で拒否し、安全でない復号へのフォールバックを一切行わないこと。また鍵・平文バッファは使用後直ちに `CryptographicOperations.ZeroMemory` で消去すること。 | 高 |
| NFR-002 | セキュリティ | XML 外部実体参照（XXE）攻撃の完全遮断 | 設定ファイルやインポート XML の解析時は常に `Authenticator.SafeReaderSettings`（`DtdProcessing = DtdProcessing.Prohibit`, `XmlResolver = null`）を使用し、DTD 宣言や外部エンティティを含む悪意ある XML を 100% 遮断（`XmlException` 送出）すること。 | 高 |
| NFR-003 | セキュリティ | ReDoS（正規表現サービス妨害）およびインジェクション対策 | アカウント識別子（Issuer / Label）解析時は `Regex.Escape` 適用および正規表現マッチタイムアウト（500ms）を設定し、悪意ある入力による CPU 枯渇・UI フリーズを防止すること。また HTML 描画時のシングルクォートエスケープ（`&#39;`）および HTTP パラメータの `Uri.EscapeDataString` サニタイズを徹底すること。 | 高 |
| NFR-004 | セキュリティ | 通信経路の暗号化強制と異常クロックドリフト防御 | 外部通信はすべて HTTPS（TLS 1.2 / TLS 1.3 強制、SSL3 / TLS 1.0 / 1.1 無効化）で行うこと。また時刻同期時にローカル時刻との乖離が絶対値で **24時間（86,400,000ms）を超える** 極端な時刻差を検出した場合は異常値として棄却し、中間者攻撃や不正な時刻注入を防ぐこと。 | 高 |
| NFR-005 | セキュリティ | エラー・ログ・クリップボードからの機密情報漏洩防止 | `InvalidEncryptionException` や `InvalidSecretDataException` 等の例外メッセージに平文シークレットキーやパスワードを含めないこと（露出 0 件）。またクリップボードへの OTP コピー時は Windows クリップボード履歴・クラウド同期除外属性を付与し、**30秒経過後** に当該コードが残存していれば自動消去すること。 | 高 |
| NFR-006 | 移行・互換性 | 旧形式データの透過的互換性と前方互換保護 | 旧バージョン（v3.x / `WINAUTH3`、v2.x）の設定ファイルをデータ欠損なく読み込み可能とし、`WINAUTH3` から `WINAUTH4` への初回更新保存時には `.v3.bak` バックアップを自動保存すること。また自バージョン（v4.0）より新しい上位バージョン（例: v4.5）の設定ファイルを読み込んだ際は例外で落とさず **`IsReadOnly = true`** を強制適用し、未知要素の上書き消失を 100% 防止すること。 | 高 |
| NFR-007 | 可用性・信頼性 | 設定ファイルのアトミック保存と破損防止 | 設定保存時はメモリ上で XML 生成・非ゼロ検証を行った後、一時ファイル（`.tmp`）へ書き出して読み戻し一致検証（バイト長・内容完全一致）を実施し、成功時のみ既存ファイルを `.bak` に退避して `.tmp` を本体へ置換すること。また相対パス指定時は起動カレントディレクトリ変動の影響を受けないよう絶対パスへ正規化すること。 | 高 |
| NFR-008 | 可用性 | ハードウェアトークン・ネイティブDLL非存在時の例外安全性 | YubiKey 用ネイティブ DLL（`WinAuth.YubiKey.x86.dll` / `x64.dll`）が埋め込まれていない開発ビルド環境や YubiKey 未接続環境においても、アンマネージドクラッシュを起こさず `LibraryNotFoundException` / `BadYubiKeyException` として安全に捕捉し、ソフトウェア認証機能の継続性を確保すること。 | 高 |
| NFR-009 | 性能 | OTP 算出レスポンスおよび起動・UI応答性 | 設定ファイルの非同期ロード（バックグラウンド `Task`）により起動時や PBKDF2 鍵導出中も UI スレッドをブロックしないこと。復号済み状態での OTP 算出および画面再描画は 50ms 以内（通常数ミリ秒以内）に完了すること。 | 中 |
| NFR-010 | UI品質・操作性 | MetroForm の動的ウィンドウリサイズ追従・高視認性フォント・多言語対応 | ウィンドウ幅の縮小・拡大時にタイトルバー制御ボタン（最小化・最大化・閉じる）および直下のバージョン表示ラベル（`versionLabel`）がクライアント領域右上に即座に追従配置され、領域外へのはみ出しや描画崩れが発生しないこと。また `Yu Gothic UI` / `Consolas`（および `ClearTypeGridFit`）により日本語・英数字を高視認に描画しつつ `AutoScaleMode.Font` 基準（`6F, 13F`）と `Webdings` ボタンを維持すること。多言語対応は埋め込み＋外部 JSON（`Japanese.json` / `English.json`）で提供し、初回は OS UI カルチャに応じて自動選択（日本語環境→`Japanese`、その他・未対応言語→`English` フォールバック）し、歯車メニューから実行中に即時切替・保存できること。 | 中 |
| NFR-011 | 運用性 | ポータブル動作の独立性と単一インスタンス制御 | `WinAuth.exe` と同階層に `winauth.xml` が存在する場合は Windows レジストリ（`Language` 設定含む）への書き込みを行わず XML 内 `<language>` / `<settings>` で完結すること。またミューテックスにより同一環境での二重起動を防止し、既存プロセスのウィンドウをアクティブ化すること。 | 中 |
| NFR-012 | 保守・配布 | CI/CD ビルド・単一バイナリ発行・通常版およびポータブル版配布の自動化 | GitHub Actions（`release.yml`）において、x86/x64 YubiKey ネイティブ DLL のコンパイル、xUnit 全単体テスト実行、`.NET 10 PublishSingleFile` による単一 `WinAuth.exe` 生成、通常版 `WinAuth-{tag}.zip` およびポータブル版 `WinAuth-{tag}-portable.zip`（`winauth.xml`同梱）のアーカイブ生成・GitHub Release 公開を 100% 自動化すること。 | 中 |
